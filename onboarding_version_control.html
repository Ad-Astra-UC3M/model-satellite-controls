Section 01

Git Installation

If you already have Git installed, skip to Section 02. To check, open a terminal and run git --version. If it prints a version number, you are good to go.

01

Download Git for Windows

Get the installer from git-scm.com/download/win.

02

Run the installer — key options

In Select Components, make sure these are checked:

  • Git LFS (Large File Support)
  • Associate .sh files to be run with Bash

In Adjusting your PATH, choose "Git from the command line and also from 3rd-party software" — this makes Git available system-wide so MATLAB can use it.

In Line ending conversions, choose "Checkout Windows-style, commit Unix-style line endings".

In Choose a credential helper, select Git Credential Manager Core.

03

Restart your computer

Required for the PATH changes to take effect.

04

Verify the installation

git --version
→ git version 2.x.x.windows.x
01

Option A — Homebrew (recommended)

Install Homebrew from brew.sh, then:

brew install git
02

Option B — Xcode Command Line Tools

Open Terminal and run git --version. If Git is not installed, macOS will prompt you to install Xcode Command Line Tools automatically.

01

Ubuntu / Debian

sudo apt update
sudo apt install git
02

CentOS / RHEL / Fedora

sudo dnf install git
Section 02

MATLAB & Git Setup

These steps need to be done once per machine. Each team member must complete them on their own computer.

Register Binary Files

Prevents Git from corrupting .slx, .mlx, .mat and other MATLAB files.

Long Path Support

Removes Windows' 260-character path limit for Git.

Simulink Auto-Merge

Lets MATLAB resolve conflicts in .slx model files automatically.

SSH Authentication

No password prompts every time you push or pull.

01

Register Binary Files with Git

In the MATLAB Command Window, run:

copyfile(fullfile(matlabroot,'toolbox','shared','cmlink','git','auxiliary_files', ...
'mwgitattributes'),fullfile(pwd,'.gitattributes'))

Verify it worked:

type('.gitattributes')
✓

You should see lines like *.slx binary, *.mlx binary, *.mat binary, *.docx binary, *.xlsx binary.

ℹ

This file lives in the repo. Once one person commits it, everyone who clones the repo gets it automatically.

02

Enable Long Path Support (Windows only)

Run this in the MATLAB Command Window:

!git config --global core.longpaths true

Verify:

!git config --global core.longpaths
→ true
03

Configure Simulink Auto-Merge

Tells Git which driver to use when it sees merge=mlAutoMerge in .gitattributes:

!git config --global merge.mlAutoMerge.name "MATLAB Auto Merge"
!git config --global merge.mlAutoMerge.driver "mlAutoMerge.bat %O %A %B %P"

Verify:

!git config --global --list
→ Look for: merge.mlautomerge.name and merge.mlautomerge.driver
04

Set Your Git Identity

Use the same email as your GitHub account:

!git config --global user.name "Your Name"
!git config --global user.email "your@email.com"
05

Set Up SSH Authentication

Allows you to push and pull without entering your password every time.

5a — Generate an SSH key

Open Git Bash and run:

ssh-keygen -t ed25519 -C "your@email.com"

Press Enter to accept the default save path. Leave the passphrase empty (press Enter twice).

5b — Start the SSH Agent (Windows — run once as Administrator)

Open PowerShell as Administrator:

Get-Service ssh-agent | Set-Service -StartupType Automatic
Start-Service ssh-agent
ssh-add C:\Users\YourName\.ssh\id_ed25519
⚠

Replace YourName with your actual Windows username. The tilde (~) shortcut does not work in PowerShell — use the full path.

ℹ

Setting StartupType Automatic means the agent starts on boot — you only need to run this block once.

5c — Add the public key to GitHub

In Git Bash, copy the key content:

cat ~/.ssh/id_ed25519.pub

Go to github.com → Settings → SSH and GPG keys → New SSH key, give it a descriptive name, and paste.

5d — Test the connection

ssh -T git@github.com
→ Hi username! You've successfully authenticated...

If prompted about host authenticity, type yes and press Enter.

5e — Enable SSH in MATLAB

Home → Settings → MATLAB → Source Control → Git → SSH: enable SSH and keep "Use SSH agent" checked.

5f — Clone the repository

MATLAB Command Window
gitclone("git@github.com:Ad-Astra-UC3M/model_satellite.git")
✓

If it returns a GitRepository object with a WorkingFolder path, the setup is complete.

Section 03

Daily Workflow

Use Git Bash or CMD as you normally would — MATLAB does not change any of that. The only difference is that you now use SSH URLs instead of HTTPS.

ℹ

MATLAB vs terminal: Use the terminal for daily push, pull, and commit. Use MATLAB's Git UI only when you need to inspect diffs on .slx Simulink files — it understands the binary format and shows a visual comparison.

Standard Daily Workflow

Git Bash / CMD
# 1. Fetch latest changes — safe, does not modify your files
git fetch origin

# 2. Check your current branch and status
git status

# 3. Update your feature branch with the latest main
git checkout main
git pull origin main
git checkout your-feature-branch
git rebase main

# 4. Make your changes in MATLAB / Simulink

# 5. Review what changed
git diff

# 6. Stage and commit
git add .
git commit -m "Add attitude control subsystem"

# 7. Push to remote
git push

Branch Strategy

Keep main always clean and functional. Each feature or subsystem gets its own branch.

# Create a new branch for your work
git checkout -b feature/power-subsystem

# Push it and set up remote tracking (first time only)
git push -u origin feature/power-subsystem

Common Commands

Command What it does When to use
git fetch Download remote changes without merging To see what others have done
git pull Download and merge remote changes When ready to incorporate remote changes
git status Show modified, staged, and untracked files Before every commit
git add . Stage all changes Before committing
git commit -m "..." Save a snapshot locally After completing a logical unit of work
git push Upload commits to GitHub To share your work with the team
git rebase main Replay your commits on top of main To keep your branch up to date
git log --oneline See recent commit history To review what has been done

Commit Message Guidelines

# Good — present tense, specific, capitalised
git commit -m "Add PID controller for attitude stabilization"
git commit -m "Fix sensor data parsing in telemetry module"
git commit -m "Update .gitattributes for Simulink binary files"

# Bad
git commit -m "stuff"
git commit -m "fixed it"
Section 04

Merge Conflicts

Simulink Models (.slx)

When two people edit the same .slx file, Git uses mlAutoMerge — configured in the setup — to resolve what it can automatically. For the rest:

  1. Open the conflicted model in MATLAB — the comparison tool will launch automatically.
  2. Accept or reject changes block by block in the visual interface.
  3. Save the file, then git add and commit.
⛔

Never try to resolve .slx conflicts manually in a text editor. The format is binary and your file will be corrupted.

Rebasing

We prefer rebase over merge to keep a clean, linear history. Rebase replays your commits on top of the latest main instead of creating a merge commit.

# Update your feature branch with latest main
git rebase main

# If a conflict occurs during rebase:
# 1. Fix the conflicted file
git add conflicted-file.slx
git rebase --continue

# To abort and return to the state before the rebase:
git rebase --abort
⚠

Never rebase commits that have already been pushed and shared with others — it rewrites history and will cause problems for the rest of the team.

Undoing Mistakes

# Discard changes to a file before staging
git restore filename.mlx

# Unstage a file after git add, before commit
git restore --staged filename.mlx

# Undo last commit but keep the changes in your working directory
git reset --soft HEAD~1
Section 05

Troubleshooting

ERR

"Permission denied (publickey)"

The SSH agent is not running. Open PowerShell as Administrator:

Start-Service ssh-agent
ssh-add C:\Users\YourName\.ssh\id_ed25519

If the service was never set to start automatically, repeat step 5b from Section 02.

ERR

"Unable to connect to SSH agent" (MATLAB)

MATLAB cannot reach the SSH agent. Check that:

  • The OpenSSH Agent service is running (see above).
  • In MATLAB: Settings → Source Control → Git → SSH — both "Enable SSH" and "Use SSH agent" are checked.
ERR

"Your branch is ahead of origin by X commits"

git push
ERR

"Your branch is behind origin by X commits"

git pull origin main
ERR

Committed to the wrong branch

# Move the last commit to the correct branch
git checkout correct-branch
git cherry-pick wrong-branch

# Remove it from the wrong branch
git checkout wrong-branch
git reset --hard HEAD~1

Still stuck?
